1. ตรวจรายการคำ/เกณฑ์จากเอกสารทางการ (ลิขสิทธิ์เป็นของผู้จัดสอบ — ต้องขออนุญาตหรืออ้างอิงเฉพาะที่เผยแพร่ได้)

4. ปรับข้อความทดสอบวัดระดับ + ป้ายมาตรฐาน

## 3. วิธีผลิตและตรวจเนื้อหา/เสียง

1. **เขียนเนื้อหา**: เขียนเองลง `data/hskN.js` ตาม schema กลาง (`W(...)`, `LESSONS`, `CHAPTERS`) — ห้ามคัดลอกรายการคำ/ข้อสอบทางการ
2. **ตรวจอัตโนมัติ** (สคริปต์ในเครื่องผู้พัฒนา): ตัวอักษรจีนตัวเต็มหลุด (OpenCC), จำนวนพยางค์พินอิน = จำนวนตัวอักษร, พินอิน/ตัวเลขวรรณยุกต์ตรงกับ pypinyin, คำใบ้อ้างอิงเสียงถูกต้อง, ข้อความ folk-etymology ต้องเป็นป้าย “ตัวช่วยจำ”
3. **เสียง**: สร้างด้วย edge-tts (เสียง Yunxi/Xiaoxiao…) → `audio/*.mp3` + `audio-index.js`; มี fallback เป็น speechSynthesis (zh-CN) ถ้าไฟล์ไม่มี
   - ⚠️ ใบอนุญาตเสียง edge-tts สำหรับใช้งานเชิงพาณิชย์ **ตรวจเบื้องต้นแล้วแต่ยังไม่ยืนยัน (ดู `AUDIO_LICENCE.md`)** — ก่อนเปิดจริงต้องเลือกผู้ให้บริการ TTS/นักพากย์ที่มีใบอนุญาตชัดเจน
4. **ตรวจโดยคน (ยังไม่ทำ)**: ผู้พูดภาษาจีนกลางเป็นภาษาแรกควรตรวจความเป็นธรรมชาติของประโยค/บทสนทนา และครูภาษาจีนสำหรับคนไทยตรวจ mnemonic และคำอ่านไทย
5. **เปรียบเทียบกับรายการ HSK 2.0 (ทำแล้ว 28 ต.ค.)**: `tools/validate.py` เทียบรายคำกับ `tools/hsk20-words.json` และรายงาน in-level % ต่อบท/ต่อระดับ

**นิยาม in-level %** (รายบทดูได้ด้วย `python3 tools/validate.py --lessons`):
- *headline* = คำที่ลิสต์ไว้ที่ระดับ ≤ ระดับของบท **หรือ** คำประกอบ/ธีมที่ทุกตัวอักษรอยู่ในคำระดับ ≤ ระดับนั้น (เช่น 动物园 จากตัว 动/物/园)
- *strict* = เฉพาะคำที่อยู่ในรายการทางการที่ระดับ ≤ ระดับของบท
- *exact* = เฉพาะคำที่รายการจัดไว้ ตรง ระดับนั้น
- เกณฑ์ของโปรเจกต์ (≥80%) ใช้ headline · strict ต่ำกว่าเพราะวลี/คำประกอบที่ไม่อยู่ในรายการ ผู้ตรวจควรดูทั้งสองตัวเลข
