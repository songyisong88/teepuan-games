# ROADMAP — เหล่าซือลามา (chinese-class-web)

> ต้นแบบทดลอง (prototype) — ไม่มี backend / การชำระเงิน / LINE จริง · เนื้อหาเขียนเอง **ไม่ใช่รายการคำหรือข้อสอบทางการ**

## 1. มาตรฐานระดับที่ใช้ (สำคัญ — อ่านก่อน)

มี HSK สองมาตรฐานที่ใช้อยู่พร้อมกัน:

| | HSK 2.0 (2012) | HSK 3.0 (ใหม่) |
|---|---|---|
| จำนวนระดับ | 6 | 9 (3 ช่วง: 1–3 / 4–6 / 7–9) |
| คำสะสม (ที่เผยแพร่/รายงานกันทั่วไป) | 150 / 300 / 600 / 1,200 / 2,500 / 5,000 | 300 / 500 / 1,000 / 2,000 / 3,600 / 5,400 … (**ตัวเลขนี้มาจากเว็บเอกชน ยังไม่ได้ยืนยันกับเอกสารทางการ**) |
| ข้อสอบรอบแรกของมาตรฐานใหม่ | — | วางแผน 13 ธ.ค. 2569 (ตามที่รายงาน ควรตรวจกับผู้จัดสอบก่อนอ้างอิง) |

**สิ่งที่แอปนี้ทำ**
- รายการคำ/ประโยค/แบบฝึก **เขียนขึ้นเอง** ในสไตล์ HSK 2.0 (`standard: 'HSK2.0-style'` ในแต่ละไฟล์ `data/hskN.js`) ไม่ได้คัดลอกรายการคำทางการและไม่ได้คัดลอกข้อสอบเก่า
- หน้าระดับ/แผนที่/README แสดงข้อความ: *“เนื้อหาอ้างอิงแนว HSK 2.0 เขียนขึ้นเอง ไม่ใช่รายการคำ/ข้อสอบทางการ”*
- ผลทดสอบวัดระดับเป็น “ตัวชี้วัดคร่าว ๆ” ไม่ใช่คะแนนสอบจริง
- **ชื่อแบรนด์/ชื่อหน้า/manifest/ข้อความ OA ไม่มีคำว่า “HSK”** — ใช้เป็นป้ายระดับภายในแอปเท่านั้น (`BRAND_NAME` = เหล่าซือลามา = ชื่อ LINE OA @282vnvnd)
- จำนวนระดับไม่ผูกกับเลข 5: `LEVELS` (data/common.js) + `LV_MAX` + `LVMETA[n]` + `stdOf(n)` — เพิ่มระดับหรือแมปเป็น HSK 3.0 ภายหลังได้โดยเพิ่มรายการใน `LEVELS` และไฟล์ `data/hskN.js` (ไม่ต้องแก้ตรรกะ)

### ถ้าจะย้ายไป HSK 3.0 (ยังไม่ได้ทำ)
1. ตรวจรายการคำ/เกณฑ์จากเอกสารทางการ (ลิขสิทธิ์เป็นของผู้จัดสอบ — ต้องขออนุญาตหรืออ้างอิงเฉพาะที่เผยแพร่ได้)
2. เพิ่ม `standard:'HSK3.0-style'` ต่อระดับ + ตารางแมป 2.0→3.0 (เช่น 2.0 ระดับ 1–2 ≈ 3.0 ระดับ 1–2 บางส่วน; ต้องทำเป็นตารางตามคำ ไม่ใช่ตามเลขระดับ)
3. ปรับเป้าคำต่อระดับ (`target`) และเพิ่มระดับ 6–9 ใน `LEVELS`
4. ปรับข้อความทดสอบวัดระดับ + ป้ายมาตรฐาน

## 2. แผนเนื้อหา HSK 1–5

เป้าคำใหม่ต่อระดับ (สไตล์ HSK 2.0): **150 / 150 / 300 / 600 / 1,300** (สะสม 150 / 300 / 600 / 1,200 / 2,500)

| ระดับ | เป้าคำใหม่ | ธีม/บท | จุดเน้นฟีเจอร์ |
|---|---|---|---|
| 1 | 150 | ตอน 1 ทักทายและตัวเลข · ตอน 2 ครอบครัวและของใช้ · ตอน 3 อาหารและเวลา · ตอน 4 เดินทาง/ซื้อของ · ตอน 5 วัน-อากาศ-กิจกรรม | วรรณยุกต์/พินอิน, ฟังและจำคำพื้นฐาน, mnemonic ภาษาไทย |
| 2 | 150 | ชีวิตประจำวัน สุขภาพ เดินทาง ซื้อของ เปรียบเทียบ | ประโยคยาวขึ้น 比 / 在…呢 / 过 / 了, role-play สั้น ๆ |
| 3 | 300 | การเรียน/ที่ทำงาน ความรู้สึก งานอดิเรก สถานที่ | ประโยคเชื่อม 虽然…但是 / 如果…就 / 把 / 被 |
| 4 | 600 | งาน สังคม สุขภาพ สิ่งแวดล้อม ความเห็น | บทสนทนายาว, แสดงความเห็น |
| 5 | 1,300 | ข่าว เศรษฐกิจ วัฒนธรรม ความคิดเชิงนามธรรม | บทอ่านยาว สำนวน |

โครงสร้างบท: 1 บท = 16 คำ + ตัวช่วยจำ (ป้าย “ตัวช่วยจำ” ไม่ใช่ที่มาของตัวอักษร) + ประโยคตัวอย่าง 6 + บทสนทนา 4 บรรทัด + แบบฝึก 2 หน่วย (หลายรูปแบบ: เลือกความหมาย, เลือกคำ, เติมคำ, ฟัง, วรรณยุกต์, เรียงประโยค, จับคู่, ตอบให้เหมาะสม)

## 3. วิธีผลิตและตรวจเนื้อหา/เสียง

1. **เขียนเนื้อหา**: เขียนเองลง `data/hskN.js` ตาม schema กลาง (`W(...)`, `LESSONS`, `CHAPTERS`) — ห้ามคัดลอกรายการคำ/ข้อสอบทางการ
2. **ตรวจอัตโนมัติ** (สคริปต์ในเครื่องผู้พัฒนา): ตัวอักษรจีนตัวเต็มหลุด (OpenCC), จำนวนพยางค์พินอิน = จำนวนตัวอักษร, พินอิน/ตัวเลขวรรณยุกต์ตรงกับ pypinyin, คำใบ้อ้างอิงเสียงถูกต้อง, ข้อความ folk-etymology ต้องเป็นป้าย “ตัวช่วยจำ”
3. **เสียง**: สร้างด้วย edge-tts (เสียง Yunxi/Xiaoxiao…) → `audio/*.mp3` + `audio-index.js`; มี fallback เป็น speechSynthesis (zh-CN) ถ้าไฟล์ไม่มี
   - ⚠️ ใบอนุญาตเสียง edge-tts สำหรับใช้งานเชิงพาณิชย์ **ยังไม่ได้ตรวจ** — ก่อนเปิดจริงต้องเลือกผู้ให้บริการ TTS/นักพากย์ที่มีใบอนุญาตชัดเจน
4. **ตรวจโดยคน (ยังไม่ทำ)**: ผู้พูดภาษาจีนกลางเป็นภาษาแรกควรตรวจความเป็นธรรมชาติของประโยค/บทสนทนา และครูภาษาจีนสำหรับคนไทยตรวจ mnemonic และคำอ่านไทย
5. **เปรียบเทียบกับรายการทางการ (ยังไม่ทำ)**: ตรวจว่าคำใดอยู่นอกระดับตามรายการทางการ (เช่น 不好意思, 麻烦, 回家, 一会儿 ถูกใช้ในบทแต่ยังไม่ได้เทียบ)

- **ผู้ตรวจอิสระดูบทด้วยสายตาไม่ครบ**: ยังมีอย่างน้อย 51 บทที่ไม่มีคนอ่านเนื้อหาจริง (ตรวจเฉพาะด้วยสคริปต์)
- **ยังไม่มีเจ้าของภาษาจีนและครูไทยตรวจ**: ความเป็นธรรมชาติของประโยค/บทสนทนา, คำแปลไทย, คำอ่านไทยและวรรณยุกต์ (เช่น 哪儿 ใน L7/L9 ที่คำอ่านไทยกำกวม)

- รายการ LOW จากรายงานตรวจ (เช่น 这个衣服→这件衣服 ใน L10, 一个鱼→一条鱼 ใน L17, เครื่องหมายจุลภาค L94, คำแปล 一会儿见 ใน L1) ยังไม่ได้แก้ทั้งหมด
- คำตอบผิดของ “ตอบให้เหมาะสม” ใช้ซ้ำหลายบท ผู้เล่นตัดตัวเลือกได้ (validator เตือน)
- เพศของบทพูดในบทสนทนาผูกกับเสียง (t หญิง / f ชาย) แต่ฟอลแบ็ก speechSynthesis ใช้เสียงเดียวปรับ pitch — ไม่ตรงกับไฟล์เสียงจริง
- เป้ากดบนมือถือ ≥44px แก้ผ่าน CSS แล้วแต่ยังไม่ได้ทดสอบกับเครื่องจริงหลายรุ่น
